The page also records two facts that are easy to get wrong: `tools:admin` is **not** a superset (grants are matched by exact key, with no implication logic), and **`tools:manage_profiles` is declared but not enforced** — no endpoint checks it in this build, and editing a tool profile currently only requires an active non-Viewer membership.

- **`PAPERCLIP_TOOL_ACTION_SIGNING_SECRET`** (MCP split 8/8) — `docs/reference/deploy/environment-variables.md` gains the new signing secret in the Deployment & Auth table. Unlike `BETTER_AUTH_SECRET` it has **no fallback**: `resolveToolActionSigningSecret()` reads only this variable and throws `ToolActionSigningSecretMissingError` when it is unset, so signed tool action approvals cannot be issued. Worktrees inherit it from `.paperclip/.env`.
