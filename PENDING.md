## ✍️ Applied this run

- **Secret folders** — new page `docs/administration/secret-folders.md`, plus a cross-reference paragraph in `docs/administration/secret-scopes.md` and a nav entry under Administration.

  Parent PR #9913 (`b94907f8`) teaches the Secrets screen to read slash-delimited secret names as a folder tree. The load-bearing fact, and the one the page is built around: **folders are derived purely from names — there is no server-side folder record.** `ui/src/pages/secrets/secret-path.ts` computes the whole tree from the name strings, so "New folder" creates nothing; it stages a path and pre-fills the create dialog's Name field with it, and the folder only becomes real once a secret is saved inside it.

  Also covered: the Folders/Flat toggle (persisted in `localStorage` under `paperclip.secrets.viewMode`, defaulting to Folders once any name contains a slash), `?path=` deep links (which force folder view for that visit), search staying deliberately flat and global, and the `12 secrets · 3 folders` counts — where the secret count includes *all* descendants, not just direct children.

  Folded in from PR #9918 (`b9f4073a`): the new `AgentSelect` in `ui/src/components/AgentMultiSelect.tsx` gives the Agent access panel a searchable picker with a **Filter agents** box. Too small for its own entry, and it belongs next to the secret it grants.

  Verification: 34/34 claims confirmed against parent code.

- **Cloud-managed instances skip the first-admin claim** — `docs/reference/api/instance-admin.md`, one new `**Cloud-managed instances.**` paragraph in the existing claim section.

  Parent PR #9912 (`2f42a496`) adds `isCloudManagedInstance()` to `server/src/middleware/auth.ts` and gates the health bootstrap check on it. Worth reading the subtlety before touching this again: the PR changed the **health** gate only. `POST /api/bootstrap/claim` in `server/src/routes/access.ts` did *not* get the same check, so on a cloud-managed instance the route still exists and still answers. What changed is that `GET /api/health` no longer reports `bootstrap_pending`, so the UI never routes anyone to the claim screen. The paragraph is worded around that user-visible outcome and deliberately does **not** claim the route 404s on cloud.
